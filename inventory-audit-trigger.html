Why audit triggers exist

Fixing values. Paper Trails.

A product was labeled 40,000 mg of sodium per serving, physically impossible. An analyst quietly corrects it to 590 mg. The number is right now. But the fact that it was ever wrong, who fixed it, and when, all erased in a single UPDATE.

How it works

An inventory audit trigger, in three steps.

No application code, the database itself writes the receipt.

01

UPDATE issued

An analyst, a script, or a vendor edits a value in product_nutrition , fixing a bad sodium reading, correcting a typo, updating a label.

→
02

Trigger fires

SQLite fires the trigger automatically. It compares OLD.value to NEW.value and only acts when they actually differ.

→
03

Audit row written

A new row lands in nutrition_audit with the old value, new value, and a timestamp. The application never touched it.

The trigger

SQL. Database Corrections.

The whole audit story is just an empty log table plus a trigger that listens for one specific change. That is the entire feature.

OLD / NEWPseudo-rows that hold both versions of the record inside the trigger body.
WHEN clauseFilters out no-op UPDATEs so the audit table doesn't fill with noise.
CURRENT_TIMESTAMPThe when of each change comes free from the database.
-- the log table
CREATE TABLE nutrition_audit (
    audit_id    INTEGER PRIMARY KEY AUTOINCREMENT,
    product_id  INTEGER NOT NULL,
    old_value   REAL,
    new_value   REAL,
    changed_at  TEXT DEFAULT CURRENT_TIMESTAMP
);

-- the trigger
CREATE TRIGGER trg_audit_sodium
AFTER UPDATE OF sodium_mg ON product_nutrition
FOR EACH ROW
WHEN OLD.sodium_mg IS NOT NEW.sodium_mg
BEGIN
    INSERT INTO nutrition_audit
        (product_id, old_value, new_value)
    VALUES
        (OLD.product_id, OLD.sodium_mg, NEW.sodium_mg);
END;

Paper trail

Why every silent fix is a silent risk.

01 · Reversibility

Undo without archaeology

If a fix turns out to be wrong, the previous value is one SELECT away.

02 · Compliance

Regulators expect it

Audit logs are a baseline expectation in finance, healthcare, and food labeling. The current state of a row is half the story.

03 · Attribution

Who changed it

Timestamp first. A user_id column fits in next. "Who edited this row in March?"

04 · Anomaly

Patterns of change

A single column getting hit every Monday is a story. The audit log surfaces data-quality problems before dashboards do.
